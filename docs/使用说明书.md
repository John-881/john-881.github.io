# 凌渡冰点的博客 · 使用说明书

这份文档是写给自己的操作手册。前提是知道 HTML 是标签、CSS 是样式，其余概念都会在这里解释一次。
需要做什么，直接跳到对应小节，不用从头读。所有命令都在 Windows + PowerShell 下验证过。

---

## 1. 先弄清这个网站是怎么运转的

一共 5 件事，理解了后面所有操作都能自己推理出来：

1. **你写的是纯文本文件**。所有文章都是 `.md` 文件（Markdown 格式，用很少的符号表示排版）。
2. **有一个程序把文本加工成网页**，这个动作叫「构建」。程序叫 Valaxy，它自己在 `node_modules/` 里，不用你管。
3. **加工结果放在 `dist/` 文件夹**，里面是普通的 `.html` / `.css` / `.js` / 图片，用浏览器直接打开就能看。
4. **上线就是把 `dist/` 里的文件传到服务器**。服务器只负责把文件发出去，不运行数据库、不执行 PHP。
5. **只有评论区不一样**：评论存在另一台服务器的数据库里，网页打开后用 JavaScript 去把评论取回来显示。

所以记住这个区别：文章是「做好的文件」，评论是「运行时去问接口」。第 9 节讲评论时还会用到。

### 1.1 名词对照表

| 会看到的词 | 说人话 |
| --- | --- |
| Node.js | 在电脑上运行 JavaScript 的程序。构建网站需要它。 |
| pnpm | 下载、管理别人写好的代码包的工具。本项目用它（`npm` 是同类工具）。 |
| 终端 / 命令行 | 输入命令的窗口。Windows 上用 PowerShell 或 Windows Terminal。 |
| 依赖（dependencies） | 别人写好的代码包。仓库里不包含它们，换台电脑要 `pnpm install` 装回来。 |
| 构建（build） | 把 `pages/` 里的 `.md` 加工成 `dist/` 里的 `.html` 等文件。 |
| 开发服务器（dev） | 只在本机临时跑起来的网站，改文件会自动刷新，用来边写边看。 |
| 端口 | 本机网站的编号。地址形如 `http://localhost:4859/`，4859 就是端口。 |
| 路由 | 网址和文件的对应关系。本站文章地址 = `/posts/` + 文件名（去掉 `.md`）。 |
| frontmatter | `.md` 文件最上方用 `---` 包起来的那段配置，写标题、日期、分类等。 |
| Markdown | 用 `#`、`**`、`-` 这类符号写排版的纯文本格式。 |
| `dist/` | 构建产物目录。它不进 git（已被 `.gitignore` 忽略），每次构建重新生成。 |
| 静态站点 | 只有现成文件、不需要后端程序的网站。本站就是。 |
| YAML | frontmatter 用的书写格式，敏感点：冒号后面要有空格，字符串建议加引号。 |

### 1.2 仓库里哪个文件夹管什么

| 路径 | 作用 | 日常要动它吗 |
| --- | --- | --- |
| `pages/posts/` | 所有文章（`.md`） | **经常** |
| `pages/moments/` | 所有说说（`.md`） | **经常** |
| `pages/` 其他子目录 | 固定页面：about、links、comment、services、subscribe、archives、categories、tags | 偶尔 |
| `media/` | 图片等媒体文件，按 `<年>/<月>/` 存 | **经常** |
| `public/` | 原样复制到网站根目录的杂项（favicon.svg、og 分享卡、1 张说说封面图；里面的 `feed.xml`/`atom.xml`/`feed.json` 是构建时自动生成的，不用管） | 很少 |
| `site.config.ts` | 站名、简介、作者、社交链接、域名等 | 偶尔 |
| `valaxy.config.ts` | 主题、首页大标题、顶部导航、页脚、评论插件配置 | 偶尔 |
| `scripts/` | 迁移时用的一次性脚本 | **不要动**（见第 13 节） |
| `waline-import/` | 评论导入用的 SQL / CSV | 不用动 |
| `docs/` | 各种说明文档（包括这份） | 不用动 |
| `backup/` | 原始 WordPress 备份包 | **不要删** |
| `.work/` | 迁移过程的报告和自检脚本 | 可以用来自检 |
| `dist/` | 构建产物 | 不用管 |

## 2. 第一次使用（换电脑时也做这些）

1. 安装 Node.js，版本要 **22.12.0 或更高**（项目 `package.json` 里写明了 `engines.node >=22.12.0`）。
2. 安装 pnpm：`npm install -g pnpm`。
3. 在项目根目录（有 `package.json` 的那一层）打开终端，装依赖：

```bash
pnpm install
```

这一步会下载几百个包，第一次要一两分钟。以后只要 `package.json` 没变就不用再装。

## 3. 最常用的两条命令

```bash
pnpm dev      # 本地预览：改文件自动刷新
pnpm build    # 生成最终成品到 dist/
```

- `pnpm dev` 跑起来后，终端会打印一个地址（通常是 `http://localhost:4859/`），用浏览器打开它。
  如果 4859 被别的程序占用，Valaxy 会自动换一个端口，**以终端打印出来的地址为准**。
- 停止运行：在终端里按 `Ctrl + C`。
- 改文章、改图片时，正在跑的 `pnpm dev` 会自动刷新，不用重启。
- **改 `site.config.ts` / `valaxy.config.ts` 之后，建议按 `Ctrl + C` 停掉再 `pnpm dev` 重开**，配置类改动不一定能热更新。

## 4. 写一篇新文章

### 4.1 步骤

1. 在 `pages/posts/` 下新建一个 `.md` 文件，**文件名就是网址**。
   - 例：文件 `pages/posts/我的新文章.md` → 网址 `http://localhost:4859/posts/我的新文章`
   - 中文文件名可以，本项目里就有很多中文网址。
   - 文件名里不要出现 `/ \ : * ? " < > |`，不要用空格，不要以点结尾。
   - **文件名定了就不要改**：改了网址就变了，旧评论会对不上（见第 9 节）。
2. 把下面这段复制到文件开头，按需修改：

```markdown
---
title: 文章标题
date: '2026-10-21 20:30:00'
categories: 玩机
tags:
  - 教程
ogImage: /og/default.png
---

这里开始写正文。

## 二级标题

段落文字。
```

3. 保存，浏览器刷新看效果。

### 4.2 frontmatter 字段表（写在 `---` 之间的部分）

| 字段 | 必填 | 怎么写 | 作用 |
| --- | --- | --- | --- |
| `title` | 是 | `title: 文章标题` | 文章标题，也用于浏览器标签页 |
| `date` | 是 | `date: '2026-10-21 20:30:00'` | 发布时间。**建议用单引号包住**，不加引号 YAML 会把它当日期对象处理，容易出问题 |
| `updated` | 否 | `updated: '2026-10-22 09:00:00'` | 最后更新时间。不写时，页面上的「更新于」参考 git 提交时间 |
| `categories` | 否 | 一个：`categories: 玩机`；多个：写成 `-` 列表 | 分类。分类页会自动列出所有用过的分类 |
| `tags` | 否 | 写成 `-` 列表，每行一个 | 标签。不写就没有标签 |
| `ogImage` | 否（但建议写） | `ogImage: /og/default.png` | 分享到微信/QQ等平台时显示的缩略图。全站用同一张 |
| `top` | 否 | `top: 10` | 置顶。数字越大排越前，不写就是不置顶 |
| `draft` | 否 | `draft: true` | 草稿，不发布显示 |
| `hide` | 否 | `hide: true` | 首页和归档列表里隐藏，但网址仍能访问 |
| `comment` | 否 | `comment: false` | 这篇文章不显示评论区 |

日期格式一律是 `'YYYY-MM-DD HH:mm:ss'`，冒号后面要有空格，这是 YAML 的规则。

### 4.3 正文用的 Markdown 速查

| 想写 | 这样写 |
| --- | --- |
| 大标题 / 小标题 | `# 一级` `## 二级` `### 三级`（文章里一般从 `##` 开始） |
| 加粗 / 斜体 | `**加粗**` / `*斜体*` |
| 无序列表 | 每行开头 `- ` |
| 有序列表 | 每行开头 `1. ` `2. ` |
| 链接 | `[显示的文字](https://example.com)` |
| 站内链接 | `[关于我](/about/)`，网址用 `/` 开头 |
| 插图 | `![](../../media/2026/10/图片名.png)`（见第 5 节） |
| 行内代码 | 用反引号包起来，例如 `` `pnpm build` `` |
| 代码块 | 三个反引号开始，写语言名（如 `js`），再用三个反引号结束 |
| 引用 | 行首 `> ` |
| 分隔线 | 单独一行 `---` |
| 表格 | 用 `|` 分隔，第二行写 `| --- | --- |` |

**两个必须记住的规则：**

1. **普通换行不会产生新行**。想让两行分成两段，中间要空一行；想在同一段里强制换行，行尾要留**两个空格**再回车。这是 Markdown 解析器的规定，不是 bug。
2. **摘要分隔符是 `<!-- more -->`**（前后各留一个空格）。放在这里之前的文字会当作列表页的摘要；不写就自动截取开头一段。

## 5. 图片怎么放（最容易出错的一节）

### 5.1 规则

1. 图片文件放到 `media/<年>/<月>/` 下，例如 `media/2026/10/screenshot.png`。
2. 文章在 `pages/posts/` 里，比 `media/` 深两层，所以正文里要用**往上两级**的相对路径：

```markdown
![](../../media/2026/10/screenshot.png)
```

3. 说说在 `pages/moments/` 里，同样是两层深，写法一样：`../../media/2026/10/screenshot.png`。

### 5.2 为什么不能用 `/images/...` 或 `/media/...`

Vite（构建工具）看到以 `/` 开头的图片地址，会把它当成「需要打包的模块」。
文件不存在时，构建会直接失败并报：

```
[UNRESOLVED_IMPORT] Could not resolve '/images/2025/03/xxx.png' in pages/posts/xxx.md
```

用 `../../media/` 相对路径的好处：构建时图片会被复制进 `dist/assets/` 并带哈希名（内容变了文件名才变，便于浏览器缓存），同一张图被多处引用也只产出一份。

唯一的例外：`pages/moments/2025-09-01-累了困了.md` 的 frontmatter 里用了 `/images/2025/12/68b55b4078002-1024x1024.jpg`，对应的文件在 `public/images/` 下。这是说说封面图需要走公共路径，**不要改它**。

### 5.3 图片注意事项

- 文件名建议英文和数字；中文可以（本项目里有），但不要用空格和特殊符号。
- 单张图尽量压到 1 MB 以内。整个站点的图片目前约 7.5 MB（迁移时把原来的 455 张去重压成了 113 张）。
- 删图片前先搜一下有没有文章引用它：`grep -rn "图片名" pages/`（或在编辑器里全局搜索）。
- 图片引用有没有写错，可以用自检脚本查（见第 11 节）。

## 6. 发一条说说（短动态）

说说显示在 `/moments/` 页面，用 `valaxy-addon-moments` 插件实现。

### 6.1 步骤

1. 在 `pages/moments/` 下新建文件，命名格式固定：`YYYY-MM-DD-标题.md`。
   - 例：`pages/moments/2026-10-21-今天学了什么.md`
   - 不写标题时用 `YYYY-MM-DD.md`；重名时自动加 `-1`、`-2`。
   - 也可以用命令生成：`pnpm valaxy moments new 标题`（按当天日期命名）。
2. frontmatter 最少要有 `date`：

```markdown
---
date: '2026-10-21 20:30:00'
title: 今天学了什么
ogImage: /og/default.png
---

说说正文写在这里，可以用和文章一样的 Markdown。
```

3. 想带图片，两种方式：
   - 正文里插图：`![](../../media/2026/10/pic.jpg)`
   - frontmatter 里写 `images`（会显示在卡片上，最多显示前 9 张）：

```yaml
images:
  - /images/2026/10/pic.jpg    # 这种写法要求文件放在 public/images/ 下
```

改完要重新构建才生效：`pnpm build`。

### 7.2 `valaxy.config.ts`：管「长什么样、有哪些入口」

| 配置项 | 作用 |
| --- | --- |
| `theme: 'yun'` | 使用的主题。换了要重新 `pnpm install` 对应主题包 |
| `themeConfig.type` | 布局风格：`nimbo`（现代）或 `strato`（经典侧栏） |
| `themeConfig.banner` | 首页大标题（`title`）。原来还有一个副标题，Yun 主题现在没这个字段，所以简介由 `description` 承担 |
| `themeConfig.pages` | **顶部导航入口**，每项是 `name`（文字）、`url`（地址）、`icon`（图标）、`color`（颜色） |
| `themeConfig.menu.custom` | 右上角那个自定义小图标（现在是 RSS，指向 `/atom.xml`） |
| `themeConfig.footer` | 页脚：`since`（建站年份）、`powered`、`beian`（ICP 备案，现在是关的，备案下来后填 `icp` 并把 `enable` 改成 `true`） |
| `addons` | 插件列表：Waline（评论）、Moments（说说） |
| `vite.ssgOptions.onFinished` | 构建结束时清洗 `dist/sitemap.xml` 的小函数（去掉 `/404` 条目和重复地址）。**不要删** |

### 7.3 加导航入口时的图标坑（重要）

图标名是从 `@iconify/json` 的 `ri` 图标集里选的（形如 `i-ri-article-line`）。
UnoCSS 会把没用到的图标样式当成垃圾删掉，所以**新用的图标名必须同时加进 `valaxy.config.ts` 顶部的 `safelist` 数组**，否则构建出来图标是空的。

查图标名是否存在：

```bash
node -e "const i=require('./node_modules/@iconify-json/ri/icons.json'); console.log(Object.keys(i.icons).filter(k=>k.includes('chat')))"
```

## 8. 固定页面（关于、友链、留言板等）

### 8.1 结构

每个固定页面是 `pages/<名字>/index.md`，网址就是 `/<名字>/`。
已有的页面：`about`（关于我）、`about/site.md`（站点历程）、`archives`（时光轴）、`categories`（分类）、`tags`（标签）、`links`（友链）、`comment`（留言板）、`services`（服务）、`subscribe`（我的订阅）。
`pages/404.md` 是找不到页面时的提示页。

写一个页面最少这样：

```markdown
---
title: 页面标题
ogImage: /og/default.png
---

页面正文。
```

**新页面记得加 `ogImage` 那一行**，不然这个页面的分享图会退化成 favicon。

### 8.2 有几种页面不能随便删

- `archives` / `categories` / `tags` 三个页面用的是主题自带布局（frontmatter 里有 `layout: archives` 之类的行），删了对应的导航入口就会 404。
- `pages/links/index.md` 的友链数据写在 frontmatter 的 `links` 数组里，每条形如：

```yaml
links:
  - name: 站点名
    url: https://example.com/
    blog: 显示名
    desc: 一句话介绍
    avatar: https://example.com/avatar.png
```

`random: false` 表示不做随机排序。

## 9. 评论系统（Waline）是怎么回事

### 9.1 现状

评论功能**现在还用不了**，因为 `valaxy.config.ts` 里的服务器地址是占位值：

```ts
addonWaline({ serverURL: 'https://your-waline.vercel.app', ... })
```

要真正启用，得先在 Vercel 上部署一个 Waline 服务端（数据库用 Neon PostgreSQL），步骤写在 `docs/waline-setup.md`，照做即可。拿到真实地址后替换上面这行，再 `pnpm build`。

### 9.2 三条必须记住的规则

1. **评论不在这个仓库里**。文章是文件，评论是数据库里的记录，两者唯一的联系是「页面地址」。
2. **文章网址变了，这条文章的旧评论就找不回来了**。所以文章文件名（也就是网址）定了就别改。
   真要改用 SQL 同步更新：`UPDATE wl_comment SET url = '新地址' WHERE url = '旧地址';`
3. **管理后台在 `<你的 Waline 地址>/ui`**。部署完成后尽快去注册，**第一个注册的账号会自动成为管理员**。

### 9.3 迁移过来的 53 条评论

- 导入文件：`waline-import/waline-comments.sql`（53 条 INSERT，含楼中楼关系）。
- 导入方法：`docs/waline-setup.md` 里第 3 节，在 Neon 的 SQL Editor 里执行。
- 旧站里的表情写法 `{{doge}}`、`{{liulei}}`、`{{dianzan}}` 已换成 `:doge:`、`:sob:`、`:thumbsup:`，对应 bilibili 表情包（已在 `valaxy.config.ts` 配好）。
- 6 条「原文章已被删除」的评论被放在了 `/comment/` 页面。

## 10. 看成品、发布上线

### 10.1 本地看成品（模拟线上）

```bash
pnpm build    # 生成 dist/
pnpm serve    # 用本地服务器预览 dist/ 里的成品
```

`pnpm dev` 和 `pnpm serve` 的区别：`dev` 是边写边看的开发模式，`serve` 看的是真实构建产物，更接近线上效果。发布前建议用 `serve` 过一遍。

### 10.2 上线

托管平台做的事都一样：安装依赖 → 运行 `pnpm build` → 把 `dist/` 当网站根目录。

| 平台 | 现成的配置文件 |
| --- | --- |
| Vercel | `vercel.json`（已配 `cleanUrls`）。新建项目时 Framework Preset 选 **Other**，Output Directory 填 `dist` |
| Netlify | `netlify.toml`（已配 `command = pnpm run build`、`publish = dist`） |
| GitHub Pages | `.github/workflows/gh-pages.yml`（推到 main 自动构建） |
| Docker / 自建 | `Dockerfile`（Node 22 构建）+ `nginx.conf` |

**上线前必须做的两件事**：

1. 改 `site.config.ts` 的 `url` 和 `author.link` 为新域名，否则 RSS 与 sitemap 里全是旧域名。
2. 改 `pages/links/index.md` 里三处示例地址（第 51、54、55 行，友链申请说明里的本站地址、图标地址、RSS 地址）。

## 12. 常见报错怎么读

| 报错信息 | 意思 | 怎么办 |
| --- | --- | --- |
| `[UNRESOLVED_IMPORT] Could not resolve '/images/xxx.png'` | 正文用了 `/` 开头的图片地址，但文件不存在 | 把图片放进 `media/年/月/`，正文改成 `../../media/年/月/xxx.png` |
| `Error: One or more pages contain dead links.` | 某个 `.md` 里链接指向了不存在的页面 | 按报错里给出的文件和地址，改链接或先把目标页面建出来 |
| `Port 4859 is in use` 之类的端口提示 | 4859 被别的程序占用 | Valaxy 会自动换端口，看终端打印的新地址；不放心就关掉占用的程序 |
| `ERR_PNPM_...` / 提示依赖需要 approve | pnpm 新版本默认不执行依赖包的安装脚本 | 本项目已配好 `pnpm-workspace.yaml`，正常安装不会遇到；真遇到按提示执行即可 |
| `You are using Node.js ... but this project requires ...` | Node 版本太低 | 升级到 22.12.0 以上 |
| 页面显示乱码或空标题 | frontmatter 写错了（缺空格、日期没加引号、缩进不对） | 对照第 4.2 节的表格逐行检查；YAML 对缩进和空格敏感 |
| 图标不显示（只剩文字） | 新用的 `i-ri-*` 图标没加进 `safelist` | 见第 7.3 节 |

## 13. 不要做的事（后果很直接）

1. **不要运行 `node scripts/wp-convert.mjs`**。它会先**删掉** `pages/posts/` 和 `pages/moments/` 里所有文件，然后只按迁移时的数据重新生成一遍。你迁移后自己新写的文章、改过的正文都会一起消失。要改文章就直接改 `.md` 文件。
   （这两个目录里现有的 31 篇文章 + 7 条说说就是它生成的，所以文件头注释会说它们是生成产物。）
2. **不要删 `backup/` 里的两个备份包**。那是唯一的原始 WordPress 数据，出问题只能靠它回退。
3. **不要把图片放 `public/` 然后用 `/images/` 引用**（除非像说说封面那样确实需要公共路径）。`public/` 里的文件只是原样复制，不做压缩，还可能和 `media/` 里的重复一份。
4. **不要改已发布文章的文件名**，评论和旧链接都会断。
5. **不要把 `dist/`、`node_modules/`、`backup/`、`.work/` 提交进 git**（`.gitignore` 已经忽略它们，别用 `git add -f` 强行加）。
6. **不要手工改 `pages/posts/` 里文章最上方那段 frontmatter 的结构**（比如删掉 `ogImage` 那一行会让人人共享的分享图失效；`date` 写坏会影响排序）。
